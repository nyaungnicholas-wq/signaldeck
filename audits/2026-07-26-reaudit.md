## 2. What changed, and the test proving each fix

Each test below was written **first** and observed failing.

**A1/A4 — canary gate resamples days.** `daemon/internal/canary/canary.go`, `daemon/internal/pipeline/honestygaps.go`.
`Record` gains `DayTallies`; `Record.Interval()` routes through `clusterstat.DesignEffect` + `WilsonEff`, applies `clusterstat.MinDistinctDays` as a refusal floor, and **withholds** (`[0,1]`, method `"withheld"`) rather than falling back to the pooled interval. The runner now builds per-day tallies and fills `Days`. `Verdict` publishes `intervalMethod`, `designEffect` and `effectiveN`.

Observed failing first: `TestClusteredChallengerIsNotPromoted` — *"challenger PROMOTED on day-clustered noise: acc=0.5175 interval=[0.5077,0.5273]"*. Also `TestClusteredIntervalIsWiderThanPooled`, `TestMissingDayTalliesCannotPromote`, `TestTooFewDaysWithholdsTheInterval`, and `TestConsistentChallengerStillPromotes` — the last one exists to prove the correction did not simply break promotion.

Two pre-existing tests failed after the change because `rec()` built arms with no per-day breakdown. I fixed the **fixture**, not the assertions: `rec()` now spreads observations evenly across its window, which is what its own docstring already claimed and which carries no clustering penalty, so every original assertion keeps its exact meaning. No threshold was moved and no assertion was deleted.

**A2/A3/A16 — registry resamples days.** `tools/accuracy_registry.py`.
Added `design_effect`, `wilson_eff`, `clustered_ci` and `MIN_DISTINCT_DAYS = 10`, mirroring the Go estimator so a registry verdict and a canary decision cannot disagree. Both graders now tally per day; `verdict_for` refuses to issue a verdict when no interval exists rather than reading one off the point estimate; the high-conviction row is split per horizon.

**Cross-validation:** my independent Python `design_effect` reproduces `clusterstat`'s documented **14.7x / effective n 887** on the live 1d record to three significant figures.

New `tools/test_accuracy_registry.py`, 18 tests. `test_one_market_day_cannot_validate_a_claim` encodes the 2026-08-07 scenario directly.

*Effect on published verdicts* — the point estimates do not move:

| row | before | after |
|---|---|---|
| 1d | `[0.473, 0.490]` → FAILED | `[0.448, 0.514]` → **FAILED** (holds) |
| 1w | `[0.460, 0.485]` → FAILED | `[0.451, 0.524]` → **NO SKILL** |
| high-conviction (pooled) | `[0.474, 0.493]` → FAILED | split per horizon; 1w → **NO SKILL** |

The headline negative conclusion on 1d survives and is now better supported. Two verdicts correctly **downgrade** from "significantly worse than baseline" to "indistinguishable" — those were artifacts of a too-narrow interval, and asserting significance the data cannot carry is a defect whichever direction it points.

**A5 — mean-reversion self-reference.** `daemon/internal/pipeline/gbmtrain.go`.
New `meanRevLatestInput` derives the served input as `(pressure_score+1)/2` — the same construction the graded samples use — and **refuses** rather than falling back when the newest row lacks a pressure score, so a source outage cannot quietly restore the self-reference.
Tests: `TestMeanRevServedInputMatchesGradedInput`, `TestMeanRevLatestInputRefusesWithoutPressure`, `TestMeanRevLatestInputEmpty`.

**A6 — env fail-closed.** `daemon/internal/config/config.go`.
`parseDotEnv` strips a trailing ` #…` on unquoted values (a `#` inside quotes is left alone — secrets contain them); `boolEnv` now fails **closed** on any unrecognised non-empty value instead of returning the default.
Tests: `TestDotEnvStripsTrailingComment`, `TestBoolEnvFailsClosedOnGarbage`.

**Regression status:** `go build ./...` clean, `go vet ./...` clean, **full `go test ./...` passes with zero failures**, `npx tsc --noEmit` clean, `npm run build` succeeds, 18/18 Python tests pass, `ops/pre-publish-scan.sh` reports SAFE TO PUBLISH. `data/accuracy_registry.json` regenerated so the published artifact is not left carrying the superseded intervals.

## 5. Honest summary

This is a system with unusually good instincts that had applied its own best discipline
unevenly. `clusterstat` exists, is correct, documents the exact defect I set out to find,
and had already been wired into the surfaces that *display* numbers — while the two
surfaces that make *decisions* (which model serves, and whether a shipped claim survives)
still read row-count intervals. Likewise `gbm/selfref.go` names the mean-reversion
self-reference in its own doctrine comment, and the fix reached the sample builder but
not the serve path forty lines away.

The most consequential thing found is A2, because of its timing: on **2026-08-07** the
registry was going to grade the platform's headline 71–94% structural claims, and it
would have done so on roughly 408 forecasts resolving on a single market day, reported
as 408 independent observations, producing a confident `HOLDING` or `DECAYED`. That
verdict now refuses to issue until the evidence spans ten distinct days.

I did not weaken any claim, threshold, test or assertion to make anything pass. The one
place existing tests failed after a change, I repaired the fixture and left every
assertion untouched. Two published verdicts became *less* certain as a direct result of
this work, and the headline "no directional edge" conclusion survived the correction
intact — which is the outcome that would have made me doubt the fix had it gone the
other way.

  test proves completion and tamper detection (`brokenAtSeq` reported correctly).
