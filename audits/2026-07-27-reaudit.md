### Things I attacked and could not break

- **Cluster-robust statistics.** I re-derived `DesignEffect` from the live rows in
  independent Python: 1d deff **14.69**, effective n **889.4** over 13,065 rows /
  24 days; 1w deff **15.13**, effective n **605.9**. The Go implementation agrees
  to the digit, and `clusterstat` genuinely refuses below 10 distinct days.
- **Registry reproducibility.** `data/accuracy_registry.json`'s headline row
  (`live_n 21`, `live_acc 0.5238`, `distinct_days 3`) reproduces exactly from a
  fresh independent query: 7+7+7 rows, 4+2+5 hits = 11/21 = 0.5238. Not stale.
- **MCP authentication.** The anonymous-loopback branch is decided from
  `config.ReachablePrivately()`, never from `RemoteAddr` — the tunnel-blind
  failure mode is genuinely closed. Fails closed on missing secret, bad
  signature, expiry, revocation and unknown scope; unknown scopes are dropped at
  verify time, not carried.
- **Outcome resolution.** Suspected a stalled 1w resolver (zero resolutions among
  rows written since 07-18). It is not stalled: every unresolved row is inside its
  own horizon or on a weekend. `MAX(resolved_at)` is 2026-07-27 08:24 (1d) and
  2026-07-26 21:54 (1w).
- **The 30-observation floor and the survivorship epoch** are consistently applied
  in the registry, the live prequential benchmark, and (after A3) the
  re-admission gate.

## 2. What changed, and the test proving each

Every fix had its failing test written and watched to fail first.

**A1 — boundary null.** `tools/accuracy_registry.py`: `wilson()` and
`wilson_eff()` now return the p=0 and p=1 endpoints exactly; `verdict_for()`
applies `VERDICT_EPS = 1e-12` **symmetrically**, so a gap inside the band yields
NO SKILL and never VALIDATED or FAILED.
*Tests:* new `TestBoundaryNullCannotManufactureAFailure` (5 cases) — 4 failed
before the fix. Two tests that had been failing on `main` for this exact reason —
`test_full_null_coverage_publishes_coverage_and_still_grades` and
`test_persistence_benchmark_row_is_emitted_and_drives_the_verdict` — now pass
without being touched.
*Not a loosened threshold:* it removes verdicts in both directions and adds none.
Registered as `PREREGISTRATION.md` §13, as §2 of that document requires.

**A3 — survivorship epoch in the re-admission gate.** New exported
`store.SurvivorshipEpoch`; `VersionedOutcomes` gained an explicit `sinceTs`;
`api.directionalShadow` passes the epoch, `pipeline`'s canary passes 0 with the
reason written at the call site (a head-to-head between two model versions is not
distorted by contamination present in both arms). `internal/pipeline`'s private
`benchmarkMajorityEpoch` now reads the one constant instead of restating it.
*Tests:* new `TestDirectionalShadowExcludesPreSurvivorshipEpochRows` — failed
before the fix with `shadow record covers 32 distinct days, want 2`;
`TestSurvivorshipEpochMatchesRegistryBoundary` pins the constant to the Python
grader's.

**A4 — e2e suite.** The harness sets `SIGNALDECK_ALLOW_DIRTY_BUILD=1` for the
child daemon, with the reason at the call site. The production guard is untouched.
*Proof:* `go test ./e2e/` → `ok … 18.899s`, where it previously failed in 3.9s
without exercising anything.

**A5 — store cache identity.** `Store` carries a process-unique `id` from a
monotonic counter; `CacheKey()` replaces `fmt.Sprintf("%p", st)` at all seven
call sites (`composite`, `attribution` ×2, `warm`, `stage5`, `xsfactor` ×2).
*Tests:* new `TestCacheKeyIsUniquePerInstanceAcrossReuse` (40 sequential
open/close/GC cycles) and `TestReaderCloneHasItsOwnCacheKey`. The probe that
motivated it measured 26/40 distinct addresses.

**A6 — liveness precondition.** `require_research_liveness()` runs inside the
grader's `main()` beside `require_registered_grader()`. Read-only; it can suppress
a publication, never repair a ledger. A database with no `worker_runs` table has
narrated nothing and is not a violation — and only that exact case passes, so an
unreadable ledger still refuses.
*Tests:* `TestGraderRefusesWithoutResearchLiveness` (3 cases).

**A7 — effective observations in the confidence floor.** `Assess` gates on
effective N, and withholds confidence together with uncertainty when no effective
size was measured; `scoreConfidence`'s sample term uses `EffectiveN/300`.
*Tests:* new `internal/confidence/independence_test.go` (4 cases) — 3 failed
before the fix.
*One pre-existing assertion was deliberately inverted*:
`TestUncertaintyReadsEffectiveNOrWithholds` required that confidence stay scorable
with no measured effective size. A quarter of the confidence composite IS a sample
term, so that path computed it from the raw row count and published "we cannot say
how uncertain this is, and we are 0.97 confident". The justification is written
into the test body, per the audit's rule that changing a pinned assertion is a
deliberate act. Nothing was loosened to make a number appear — a number stopped
appearing.

## 4. What I could not verify, and the exact command that would settle it

1. **That A2's fix works.** Rebuilding and restarting a live service is an
   operator action and I did not take it. The sequence:
   ```bash
   cd "$HOME/claude code/signaldeck" && ./ops/signaldeck-ctl.sh deploy
   ```
   then confirm the registrar writes a complete record:
   ```bash
   sqlite3 "file:data/signaldeck.db?mode=ro" "SELECT spec_json FROM prereg_records WHERE kind='grading-protocol' ORDER BY seq DESC LIMIT 1;" | python3 -m json.tool
   ```
   It must carry `minDistinctBlocks`, `maxAlpha` and `multiplicityRule`. Note the
   deploy builds from `git archive HEAD`, so **this audit branch must be merged
   first** — and every fix in it is inert until that deploy runs.

2. **That the amended grader grades end-to-end.** It cannot run until the
   registrar appends the new digest (§13 of `PREREGISTRATION.md`, and A2 blocks
   that pass). After the deploy:
   ```bash
   python3 tools/accuracy_registry.py --json /tmp/reg.json && python3 -m json.tool /tmp/reg.json | head -40
   ```
   I verified the graded rows by calling `grade_directional()` directly against a
   read-only connection, which skips only the registration gate.

3. **A8's README/registry drift.** It clears on the next successful
   `ops/accuracy-registry.sh` run, which A2 blocks. I did not hand-sync the README
   because doing so would publish numbers the liveness gate (A6) would have
   refused. Once A2 is cleared, the drift is worth a standing check — the
   rendering half of that script is a heredoc, so extracting it to
   `ops/render_readme_accuracy.py` would make "README matches the registry" a
   testable assertion rather than a convention.

4. **The 48-rule grid search with no judgment ledger** (`worker_runs id=139413`).
   The liveness checker reports it and I did not repair it — repairing a ledger
   from an audit is exactly the move that would make the ledger meaningless. The
   research loop that narrated it needs to write `research_loop_judgments`, or the
   narration needs to stop:
   ```bash
   sqlite3 "file:data/signaldeck.db?mode=ro" "SELECT id, datetime(started_at,'unixepoch'), detail FROM worker_runs WHERE worker='research-loop' AND status='ok' ORDER BY id DESC LIMIT 5;"
   ```

5. **`cmd/sdmaint` (494 lines), `cmd/selfref-ablation` (396) and
   `cmd/signaldeck-mcp` (141) have no test files at all.** I read them and found
   nothing wrong, but "I read it" is not coverage and I am not claiming it as one.
   `internal/mcp` itself is well covered (attack, auth, budget, allowlist suites).

## 5. Honest summary

Nine findings, seven fixed with tests that failed first, one diagnosed and handed
to the operator because it needs a redeploy, one proposed. The two that matter are
**A1**, where a float64 epsilon could retire a model that tied its null, and
**A2**, where the deployed daemon and its own grader disagree about the
registration protocol badly enough that the accuracy registry cannot be regraded
at all until someone redeploys.

The system's honesty machinery is real and it worked: the liveness checker caught
a narrated search with no ledger, the registration check caught an unregistered
grader (mine), and the document-claims test caught the deadlock. What it could not
do was be heard — `go test ./...` was red for an unrelated reason on every working
tree, so the one test reporting a production outage was sitting in the noise.
Restoring that signal (A4, A5) is probably worth more over the next month than any
single fix in this report.
